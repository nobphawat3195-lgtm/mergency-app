# 2. โครงสร้างแอป (Information Architecture)

## แอปทั้งหมด 2 ตัว (แยกเหมือน 24CarFix)

- **App ลูกค้า** (Customer App) — เรียกช่าง / จองตรวจรถ
- **App ผู้ให้บริการ** (Provider App) — ใช้ร่วมกันทั้งช่างซ่อมและผู้เชี่ยวชาญตรวจสภาพ แต่แยก mode ตาม role

## Bottom Navigation (Customer App) — 4 แท็บ

```
[หน้าหลัก]  [รายการ/ประวัติ]  [แชท AI]  [โปรไฟล์]
```

## Home Screen — Hierarchy

```
Home
├── Location Picker (header)
├── Hero Cards (2 คอลัมน์)
│   ├── เรียกช่างฉุกเฉิน (badge: แนะนำ)
│   └── รถสไลด์/รถยก
├── Secondary Cards
│   ├── บริการมอเตอร์ไซค์
│   ├── สั่งอะไหล่ใกล้ฉัน
│   └── ผู้ช่วย AI (แชทบอทให้คำแนะนำเบื้องต้น)
├── Banner Carousel (โปรโมชัน)
├── หมวดหมู่บริการ (grid 4 คอลัมน์)
│   ├── ช่างซ่อมรถยนต์
│   ├── ช่างแบตเตอรี่
│   ├── ช่างปะยาง
│   ├── ช่างกุญแจ
│   ├── ช่างรถ EV
│   ├── ทำสีรถยนต์
│   ├── พ่นกันสนิม
│   └── ล้างแอร์รถยนต์
└── [ใหม่] การ์ดเด่น "ตรวจรถมือสองก่อนซื้อ" (แยกให้เห็นชัด ไม่ปนกับ grid ซ่อมรถ)
```

## 2 Flow หลัก

### Flow A: Emergency (ของเดิม ปรับปรุง)
```
Home → เลือกหมวดบริการ → บริการย่อย → ประเภทรถ → ประเภทย่อย
  → สรุปราคา → ยืนยัน → จับคู่ช่าง → ติดตามช่างแบบ real-time
  → ช่างถึงที่/ดำเนินการ → ปิดงาน + ชำระเงิน → ให้คะแนน
```

### Flow B: Pre-purchase Inspection (ใหม่)
```
Home → "ตรวจรถมือสองก่อนซื้อ" → กรอกข้อมูลรถ + สถานที่นัด
  → เลือกแพ็กเกจตรวจ (Basic/Full) → เลือกวันเวลานัด
  → จับคู่ผู้เชี่ยวชาญที่ผ่านการรับรอง → ยืนยัน + ชำระเงินมัดจำ
  → [รอวันนัด] → ผู้เชี่ยวชาญตรวจหน้างาน (ฝั่ง Provider App กรอก checklist)
  → รายงานผลส่งเข้าแอปลูกค้าทันที (scorecard + รูป/วิดีโอ + PDF)
  → ลูกค้าตัดสินใจซื้อ/ไม่ซื้อ + ให้คะแนนผู้เชี่ยวชาญ
```

## หน้าประวัติ/รายการ (แท็บ 2)

แยกเป็น 2 sub-tab: "งานซ่อม/ฉุกเฉิน" กับ "งานตรวจรถ" เพราะสถานะและข้อมูลที่แสดงต่างกันมาก (งานซ่อมดูสถานะ real-time, งานตรวจดูรายงานผลย้อนหลัง)
