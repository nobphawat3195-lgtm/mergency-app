# 8. สรุปเวิร์กโฟลว์สุดท้าย + การตัดสินใจทั้งหมด (ก่อนเริ่มเขียนโค้ด)

เอกสารนี้รวมทุกการตัดสินใจจากรอบ grilling ทั้งหมด ใช้เป็น source of truth ก่อนเริ่ม scaffold โค้ดจริง

## สรุปการตัดสินใจหลัก

| หัวข้อ | ผลสรุป |
|---|---|
| ขอบเขต MVP | Emergency flow เท่านั้น (Inspection ทำ Phase 2) |
| พื้นที่เปิดตัว | กรุงเทพฯ/ปริมณฑล |
| ช่างเริ่มต้น | มี 10 คน พร้อมเครื่องมือ/อุปกรณ์ครบ |
| แอป | แยก 2 แอป: Customer App + Provider App (เหมือน 24CarFix) |
| Framework | Flutter (2 แอป จาก 1 codebase pattern, ทีมพัฒนาโดย AI ทั้งหมด) |
| Backend | NestJS + PostgreSQL (ไม่ใช้ Firebase เพราะมีระบบการเงิน/wallet ต้องการ ACID) |
| การจับคู่งาน | Auto radius-based dispatch — ส่งงานให้ช่างที่ใกล้สุดก่อน |
| Timeout รับงาน | 90 วินาที/รอบ เสนอพร้อมกัน 4 คน ไม่รับ → ส่งต่อชุดถัดไปอัตโนมัติ |
| การชำระเงินลูกค้า | ในแอปเท่านั้น ผ่าน PromptPay เป็นหลัก (หลีกเลี่ยง hold 7 วันของบัตรเครดิต) |
| ค่าคอมมิชชัน | หัก 35% ทุกงานเท่ากัน |
| การเบิกเงินช่าง | กดขอเบิกได้ตลอดเวลา (on-demand) แอดมินโอนเองผ่านมือถือทันทีที่เห็น request |
| Admin Dashboard | ต้องมี (เว็บแอป) — จัดการช่าง/อนุมัติช่างใหม่/อนุมัติเบิกเงิน/ดูออเดอร์ |
| การลงทะเบียนช่าง | ช่างสมัครเองผ่าน Provider App (เบอร์+OTP) แอดมินกดอนุมัติ |
| ข้อมูลที่ช่างต้องกรอก | ดู "แบบฟอร์มลงทะเบียนช่าง" ด้านล่าง (อิงมาตรฐาน 24CarFix Fixer) |
| Auth | เบอร์โทร + OTP ทั้ง 2 แอป |
| ราคาบริการ | ใช้ baseline จากภาพตัวอย่าง 24CarFix เก็บเป็นข้อมูลใน DB (แก้ไขได้ ไม่ hardcode) |
| แนบรูปตอนสร้างออเดอร์ | มีตั้งแต่ MVP |

## Workflow เต็มระบบ (End-to-End)

### A) ฝั่งช่างสมัครเข้าระบบ (ก่อนเปิดใช้งานจริง)

```
ช่างโหลด Provider App
  → สมัครด้วยเบอร์โทร + OTP
  → กรอกแบบฟอร์มลงทะเบียน (ดูรายละเอียดด้านล่าง)
  → ส่งคำขอเข้าระบบ (status: pending)
  → แอดมินตรวจสอบเอกสาร → กดอนุมัติ (status: verified)
  → ช่างเข้าสู่ระบบได้ กด "ออนไลน์" เพื่อเริ่มรับงาน
```

#### แบบฟอร์มลงทะเบียนช่าง (ฟอร์มจริงที่ใช้คัดกรองช่างของธุรกิจนี้)

นี่คือฟอร์มจริงที่ใช้อยู่แล้ว (คัดกรองผ่าน LINE/Facebook ก่อนเปิดใช้แอป) — ใช้เป็น field list ตั้งต้นของหน้าลงทะเบียนใน Provider App โดยตรง ไม่ต้องเดาแบบรอบก่อน:

**ขั้นตอนที่ 1 — สมัคร (กรอกในแอปตอนสมัคร)**
- ชื่อจริง - ชื่อเล่น
- ชื่อร้าน/อู่ (ถ้ามี — ไม่บังคับ)
- เบอร์โทรศัพท์ (ยืนยันด้วย OTP)
- แชร์โลเคชั่นร้าน/พื้นที่รับงาน (ปักหมุด — ใช้คำนวณรัศมี dispatch)
- วันและเวลาเปิด-ปิด (ช่วงเวลาพร้อมรับงาน)
- งานบริการที่รับทำ (เลือกได้หลายอย่าง: ไดนาโม/แบตเตอรี่/ยาง/กุญแจ/เครื่องยนต์/ลากรถ ฯลฯ)
- ประเภทรถที่รับ (มอเตอร์ไซค์ / รถยนต์ / รถยุโรป / รถบรรทุก / เครื่องจักร — เลือกได้หลายอย่าง)
- ชื่อเพจ/เฟซบุ๊ก (ใช้เป็นหลักฐานความน่าเชื่อถือ/ตัวตนทางธุรกิจ แทนการขอเอกสารราชการ)
- รูปเครื่องมือช่าง (อัปโหลด — ใช้ยืนยันว่าเป็นช่างจริงมีอุปกรณ์พร้อมทำงาน)

**ขั้นตอนที่ 2 — หลังแอดมินอนุมัติ (กรอกก่อนเปิดใช้ฟีเจอร์เบิกเงิน)**
- บัญชีธนาคาร/เบอร์พร้อมเพย์ สำหรับรับเงินเข้า wallet (แยกออกจากฟอร์มสมัครหลัก เพราะฟอร์มจริงที่ใช้อยู่ไม่ได้ขอไว้ตั้งแต่ต้น — ขอตอนช่างเข้าระบบแล้วก่อนกดเบิกเงินครั้งแรกก็เพียงพอ)

หมายเหตุ: ฟอร์มจริงไม่มีการขอเลขบัตรประชาชน/สำเนาบัตร — ใช้ชื่อเพจ/เฟซบุ๊กและรูปเครื่องมือแทนการยืนยันตัวตนที่เข้มงวด เหมาะกับการเริ่ม pilot เร็ว ถ้าอนาคตอยากเพิ่มความเข้มงวด (เช่น scale ใหญ่ขึ้น) ค่อยเพิ่มขั้นตอน KYC ทีหลังได้

### B) ฝั่งลูกค้าเรียกช่างฉุกเฉิน (Flow หลัก)

```
เปิดแอป → เลือกตำแหน่ง (GPS อัตโนมัติ/ปักหมุดเอง)
  → เลือกหมวดบริการ (Step 1/4)
  → เลือกบริการย่อย (Step 2/4) — เห็นราคาทันที
  → เลือกประเภทรถ (Step 3/4)
  → เลือกประเภทย่อย + แนบรูปปัญหา (ไม่บังคับ) (Step 4/4)
  → สรุปราคา → ยืนยัน
  → [ระบบ dispatch เริ่มทำงาน — ดู C]
  → ติดตามช่างแบบ real-time บนแผนที่
  → ช่างถึงที่ → ดำเนินการซ่อม
  → ช่างปิดงานในแอป Provider → ลูกค้าเห็นสรุปค่าใช้จ่าย
  → ลูกค้าชำระเงินผ่าน PromptPay ในแอป
  → ให้คะแนน + คอมเมนต์
```

### C) ระบบ Dispatch (Auto-matching)

```
ออเดอร์ใหม่เข้าระบบ
  → ระบบคำนวณระยะทางช่างที่ "ออนไลน์" ทุกคน จากตำแหน่งปัจจุบัน
  → เรียงจากใกล้สุด → ไกลสุด
  → ส่งข้อเสนอให้ช่างใกล้สุดรอบละ 4 คน (นับถอยหลัง 90 วินาที)
     ├── กดรับ → จบ dispatch, มอบหมายงานให้ช่างคนนี้
     └── ไม่ตอบสนอง/ปฏิเสธ → ส่งต่อช่างอันดับ 2 ทันที (วนซ้ำ)
  → ถ้าช่างทุกคนปฏิเสธ/ไม่ตอบ → แจ้งเตือนแอดมิน + แจ้งลูกค้าว่ากำลังหาช่างเพิ่ม
```

### D) ระบบเงิน (Payment → Commission → Wallet → Withdrawal)

```
ลูกค้าชำระเงินเต็มจำนวนผ่าน PromptPay ในแอป
  → เงินเข้าบัญชีบริษัท (same-day/next-business-day settlement)
  → ระบบหักคอมมิชชัน 35% อัตโนมัติ
  → เครดิต 65% ที่เหลือเข้า "กระเป๋าเงินในแอป" ของช่างทันที (เป็นตัวเลขในระบบ ยังไม่ใช่เงินจริงในบัญชี)
  → ช่างเห็นยอดในกระเป๋า กดปุ่ม "ขอเบิกเงิน" เมื่อไหร่ก็ได้
  → คำขอเบิกเข้า admin dashboard ทันที (push notification ให้แอดมิน)
  → แอดมินตรวจสอบ + โอนเงินจริงผ่านแอปธนาคาร/พร้อมเพย์ด้วยตัวเอง
  → กดยืนยัน "โอนแล้ว" ในระบบ → สถานะกระเป๋าช่างอัปเดตเป็น "เบิกแล้ว"
```

### E) Admin Dashboard (เว็บแอป — ทำคู่ขนานกับ Mobile Apps)

หน้าที่หลัก:
1. อนุมัติ/ระงับบัญชีช่าง
2. Monitor ออเดอร์ real-time ทั้งหมด (กำลังหาช่าง / กำลังดำเนินการ / เสร็จแล้ว)
3. จัดการคำขอเบิกเงิน (อนุมัติ + mark ว่าโอนแล้ว)
4. จัดการราคาบริการ/หมวดหมู่ (แก้ไขได้โดยไม่ต้อง deploy โค้ดใหม่)
5. Dashboard สรุปยอด: จำนวนออเดอร์, รายได้คอมมิชชัน, เรตติ้งเฉลี่ย

## สถานะออเดอร์ (State Machine)

```
created → searching → matched → en_route → in_progress → completed
                  ↘ no_match (ครบ timeout ทุกคน) → escalated_to_admin
             ↘ cancelled (ลูกค้ายกเลิกก่อน matched)
```
